## 1 引言

### 1.1 编写目的

说明本软件的体系结构、模块划分、数据组织与关键处理流程，供开发维护、技术评审及软件著作权登记备查。

### 1.2 项目背景

双色球开奖数据与奖池、投注等市场指标长期公开。本软件在本地完成数据汇聚与统计分析，以 Web 方式呈现结果，强调**市场可分析、号码近随机**的科学边界。

### 1.3 定义与缩写

| 术语 | 说明 |
|------|------|
| SSQ | 双色球 |
| DataHub | 统一数据与特征中枢 |
| Regime | 市场状态聚类类别 |
| LUT | 反向查询查找表 |
| Soft reinit | 进程内增量扩展模型标签 |

## 2 系统总体设计

### 2.1 架构风格

本地 **B/S**：浏览器 + Flask 服务 + 本地文件/SQLite。

```
┌─────────────┐     HTTP      ┌──────────────────┐
│  浏览器 UI   │ ←──────────→ │  Flask app.py     │
└─────────────┘               │  + APScheduler    │
                              └────────┬─────────┘
                                       │
              ┌────────────────────────┼────────────────────────┐
              ▼                        ▼                        ▼
        engine/* 分析引擎         data/* 本地数据          web/static 静态资源
        (market/numbers/          (json/sqlite/           (brand 完整自包含)
         validator/predictor)      report)
```

### 2.2 逻辑分层

| 层次 | 职责 | 主要组件 |
|------|------|----------|
| 展示层 | 页面与交互 | `web/templates/index.html` |
| 接口层 | REST/页面路由、调度 | `app.py` |
| 应用层 | 预测编排、复式、进化 | `predictor.py`, `evolution.py` |
| 领域层 | 市场/号码/行为/验证/排序 | `market`, `numbers`, `behavior`, `validator`, `ranker` |
| 数据层 | 爬取、存储、特征 | `crawler`, `data_hub`, `data/` |
| 运维层 | CLI、Makefile、测试 | `scripts/`, `tests/` |

### 2.3 部署视图

单机部署即可。生产建议 `gunicorn -w 1` 单进程，避免多 worker 重复调度与内存模型分裂。

## 3 功能模块设计

### 3.1 数据爬取与合并（Crawler + DataHub）

- 输入：公开历史页 HTML  
- 处理：解析期号、红蓝球、奖池、投注、奖级、日期；校验范围与互异性  
- 输出：合并入 `ssq_all.json`，upsert `draws` 表；可选回填 `predictions` 命中  

### 3.2 特征工程（DataHub）

- 红球特征张量、市场 14 维矩阵、期画像、蓝球遗漏  
- 向量化实现以降低加载时延  
- `issue_to_t` 映射供验证器按期定位  

### 3.3 市场模型（MarketModel）

- GMM 五类 Regime  
- 奖池→投注、投注→头奖线性反馈  
- KMeans 离散态 Markov 及五类转移  
- Soft extend：冻结变换，仅预测新增期标签  

### 3.4 号码与行为（NumberModel / BehaviorModel）

- 无条件/条件结构分布、拒绝采样生成候选  
- 成本分与近窗频率  
- 拥挤度复用成本分  

### 3.5 验证器（Validator）

- 前向：组合→估计头奖注数  
- 反向：按头奖注数或条件距离找历史邻域，统计前期 Regime  
- 一致性 = 当前 Regime 概率与分布集中度加权  
- 批量路径使用 prize LUT，避免重复查询  

### 3.6 排序与编排（Ranker / Predictor）

- 默认：按一致性排序  
- 实验：抗拥挤、结构 LL、市场拟合加权为 final  
- 输出 JSON 报告并落盘  

### 3.7 Web 与调度

- 路由：主页、预测、更新、历史、对照、状态等  
- Cron：开奖日 22:00 更新  
- 启动策略：数据过期则后台抓取

## 4 数据设计

### 4.1 逻辑数据

见工程 `docs/data_structure.md`。核心实体：

- **Draw（开奖）**：期号、红1–6、蓝、奖池、投注、一/二等奖、日期  
- **PredictBatch / Prediction**：批次、目标期、单注/复式、评分、命中  

### 4.2 物理存储

| 文件/表 | 用途 |
|---------|------|
| ssq_all.json | 权威全量备份 |
| ssq.db / draws | 查询加速 |
| ssq.db / predictions | 对照与回填 |
| predict_result.json | 最近报告缓存 |

### 4.3 静态资源

`web/static/brand/` 内含 favicon、产品 logo、实验室主 LOGO 完整 SVG/PNG，**无外链依赖**。

## 6 关键处理流程

### 6.1 快速分析

```
加载/确认 DataHub
→ 市场状态
→ 采样候选
→ batch_validate（LUT）
→ [可选 multi rank]
→ 复式规划
→ 写 predict_result.json
→ 前端渲染
```

### 6.2 数据更新

```
fetch 远端
→ merge 本地 JSON/SQLite
→ backfill hits
→ soft/full reinit
→ 快速分析流程
```

## 7 安全与可靠性设计

- 默认绑定可配置；生产应置于受信网络  
- SQLite 访问加锁，降低并发写冲突  
- 更新互斥锁防止重入  
- 失败时保留上次预测结果

## 9 限制与假设

1. 依赖公开网页结构稳定；源站变更可能导致爬虫失效。  
2. 号码本身不具有可稳定预测性；评分不作中奖保证。  
3. 单机部署为主，未实现多租户与账号体系。
